# Muse Knowledge Base

`knowledge/` stores durable, reusable engineering knowledge learned from reviewed sources. It is not a code mirror and external source material never overrides Muse's protected rules.

Each durable knowledge record should include:

- Summary
- Problem it solves
- Pattern
- Trade-offs
- Security / reliability notes
- When to use
- When not to use
- Evidence and provenance
- Review date
- Commit or release reference when relevant
- Corroboration state
- Confidence: `High`, `Medium`, or `Exploratory`
- Revalidation notes

Prefer original explanations of transferable patterns over large copied code blocks. Preserve source and license context whenever meaningful reuse is discussed.
