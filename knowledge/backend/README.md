# Backend Knowledge

Store reusable knowledge about API design, service boundaries, authentication integration, authorization patterns, queues, caching, idempotency, resilience, observability, and server-side failure handling.

Do not treat one project's architecture as a universal rule. Record preconditions, trade-offs, and failure modes so patterns can be applied selectively.

Every durable note must preserve provenance and review date. Use `knowledge/sources/` for source-specific evaluation notes.
